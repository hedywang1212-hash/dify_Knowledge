# Markdown 知识库优化设计

## 目标

批量整理仓库根目录下的四个 Markdown 文件，使其更适合 AI 知识库的文本切片、语义检索和问答，同时修复图片链接并为每张图片添加可独立理解的文字说明。

## 处理范围

- `001_ACL知识整理.md`
- `002_获取URL参数值.md`
- `003_多语言自适应Message带参数的实现.md`
- `004_如何修改table里field的颜色.md`

不处理当前已删除的 `ACL.md` 和 `README.md`，也不改变 `images` 目录中的图片文件。

## 内容整理原则

1. 每篇文档仅使用一个一级标题，并用二级、三级标题组织主题。
2. 保留原文的技术结论和操作意图，修正明显的错别字、语病、大小写、空格及术语表达。
3. 根据原文补充必要的上下文，不引入无法从原文或截图确认的 ServiceNow 行为。
4. 每篇增加简短的概述和核心要点，使知识库切片在脱离全文时仍能表达主题。
5. 操作型内容整理为有序步骤；并列结论和注意事项使用无序列表。
6. 代码块使用 `javascript` 语言标记，统一缩进，并将含义不清的占位符改为可读示例或文字说明。
7. 首次出现的重要 ServiceNow 术语提供中英文或完整名称，提升关键词召回率。

## 图片处理

图片使用以下 GitHub Raw 基础地址：

```text
https://raw.githubusercontent.com/hedywang1212-hash/dify_Knowledge/main/images/
```

链接中的文件名和扩展名必须与 `images` 目录中的实际文件一致：

- `001_01.jpg`
- `004_01.png`
- `004_02.png`

所有图片均使用有意义的替代文本。图片后紧跟以“图片说明：”开头的文字，描述截图中的关键界面、操作或逻辑，不仅重复替代文本。

## 各文档的整理重点

### 001 ACL 知识整理

- 明确表级 ACL、字段级 ACL、同级 OR 关系和跨级 AND 关系。
- 整理通配符、规则组成、继承、管理员覆盖、调试和其他 ACL 类型。
- 优化现有 ACL 逻辑图的替代文本和图片说明。

### 002 获取 URL 参数值

- 按客户端、服务端和 Service Portal Widget 三种环境组织方法。
- 补充方法用途、返回值和必要的注意事项。
- 规范客户端与服务端代码示例。

### 003 多语言 Message 参数化

- 区分客户端 `getMessage()` 和服务端 `gs.getMessage()`。
- 整理无参数消息与带占位符消息的实现方式。
- 将创建 `sys_ui_message` 记录和调用代码拆分为清晰步骤。

### 004 修改表字段颜色

- 增加适用场景、操作步骤和配置字段解释。
- 将两条错误的 `.jpg` 链接修正为实际存在的 `.png` 文件。
- 第一张图说明字段右键菜单中的 `Configure Styles` 入口。
- 第二张图说明 Styles 列表中的 Table、Field name、Value 和 Style 配置。

## 验收标准

1. 四篇 Markdown 均具有清晰标题、概述、主体章节和必要的注意事项。
2. Markdown 标题、列表、代码块和空行格式一致，不含不可见的零宽字符。
3. 所有图片 URL 与本地实际文件一一对应，扩展名正确。
4. 每张图片下方均有基于图片内容的说明。
5. 不存在旧的错误图片链接或空替代文本。
6. Git 差异仅包含四篇目标文档和本设计文档，不覆盖用户已有删除状态。
